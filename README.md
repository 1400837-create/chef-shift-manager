# Kitchen OS — PWA для управления кухней

Мобильное PWA-приложение для шеф-повара: смена, меню, склад с FIFO, уборка и финансы.
Все данные хранятся локально в браузере (`localStorage`) — сервер не нужен.

## Стек

- React 18 + Vite
- Tailwind CSS
- lucide-react (иконки)
- `localStorage` для персистентности данных
- Service Worker для офлайн-режима и установки как приложение (PWA)

## Локальный запуск (с нуля)

Если у вас ещё не установлен Node.js — поставьте LTS-версию с https://nodejs.org (18+).

```bash
cd chef-shift-manager
npm install
npm run dev
```

Откроется адрес вида `http://localhost:5173/chef-shift-manager/` — открывайте его с телефона
(в той же Wi-Fi сети, через `http://<IP-компьютера>:5173/...`) или тестируйте в браузере
на компьютере с открытым мобильным видом (DevTools → Toggle device toolbar).

## Данные и хранилище

Всё состояние приложения хранится в `localStorage` под ключами с префиксом `kitchenOS_`
(например `kitchenOS_inventoryItems`, `kitchenOS_menuData`). Ничего не отправляется на сервер.

**Важно:** `localStorage` привязан к браузеру и устройству. Если чек-лист откроют
на другом телефоне или в другом браузере — данных там не будет. Если нужна синхронизация
между устройствами/сотрудниками, это отдельная (серверная) доработка вне рамок MVP.

Экспорт/бэкап данных вручную: в DevTools → Application → Local Storage можно скопировать
значения. При необходимости легко добавить кнопку "Экспорт в JSON" — сообщите, если нужно.

## Деплой на GitHub Pages

### Вариант А — автоматически через GitHub Actions (рекомендуется)

1. Создайте репозиторий на GitHub, например `chef-shift-manager`.
2. Если имя репозитория отличается — поправьте `base` в `vite.config.js`
   и `start_url`/`scope` в `public/manifest.webmanifest`, а также пути `/chef-shift-manager/`
   в `index.html` и `public/sw.js` на `/<ваше-имя-репозитория>/`.
3. Запушьте код:
   ```bash
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/chef-shift-manager.git
   git push -u origin main
   ```
4. В настройках репозитория: **Settings → Pages → Source → GitHub Actions**.
5. Workflow `.github/workflows/deploy.yml` соберёт и опубликует сайт при каждом push в `main`.
6. Сайт появится по адресу `https://<ваш-логин>.github.io/chef-shift-manager/`.

### Вариант Б — вручную через пакет `gh-pages`

```bash
npm install
npm run deploy
```

Это соберёт проект и запушит папку `dist` в ветку `gh-pages`. Затем в
**Settings → Pages → Source** выберите ветку `gh-pages`.

## Импорт из Google Таблиц

Прямого подключения к Google Sheets API нет — сайт статический (GitHub Pages, без
бэкенда), а публичный CSV-экспорт Google Docs не отдаёт CORS-заголовки, так что
`fetch()` из браузера с большой вероятностью будет заблокирован. Поэтому импорт
сделан через копирование-вставку, что работает всегда и не требует ни ключей,
ни авторизации:

1. В Google Таблице выделите нужный диапазон ячеек и скопируйте (Ctrl+C) —
   Google Таблицы копируют данные с табуляцией между столбцами.
2. В приложении откройте панель импорта (**Меню** → «Импорт из Google Таблиц»,
   или **Склад & FIFO → Переучёт** → «Импорт каталога из Google Таблиц») и
   вставьте (Ctrl+V) в текстовое поле.
3. Нажмите «Импортировать».

Ожидаемые столбцы:
- **Меню:** День (число 1–31), затем сколько угодно столбцов с блюдами (первые
  5 подставляются как «Суп, Горячее, Гарнир, Салат, Напиток», дальше — «Блюдо 6», «Блюдо 7»…),
  последний столбец опционально — Кошер (да/нет).
- **Каталог для переучёта:** Название, [Ед. изм.], [Зона: холодильник / морозильник / сухой склад].

Парсер (`src/utils/importParsers.js`) терпим к формату: не обязательно точно
5 или 3 столбца, лишние ячейки игнорируются, а зона распознаётся по ключевым
словам (если не указана или не распознана — попадает в «Сухой склад»).

## Номенклатура продуктов (Склад & FIFO → Каталог)

Единый список продуктов (`recountCatalog`), общий для Переучёта, Остатков,
закупок и рецептов — один и тот же товар, а не отдельные списки в разных
местах. Кнопка «Загрузить базовую номенклатуру» одним нажатием добавляет ~70
позиций (мясо; курица/индейка и их части — филе, бедро, голень, крыло,
потроха; овощи; фрукты; бакалея; специи) — пропускает то, что уже есть в
каталоге по названию, так что нажимать безопасно повторно. Список полностью
редактируемый вручную: название, единица измерения и зона хранения каждой
позиции — прямо в списке, без отдельного режима редактирования. Все свободные
текстовые поля с названиями продуктов в приложении (Склад → FIFO → Название,
Дашборд → учёт овощей/фруктов) подсказывают варианты из этого каталога через
`<datalist>` (`src/App.jsx`, `id="product-nomenclature"`).

## Полный переучёт (Склад & FIFO → Переучёт)

Отдельная вкладка для помесячного пересчёта фактических остатков — отличается
от обычного чек-листа «Проверка зон» тем, что здесь ведётся каталог конкретных
товаров с количеством, а не общий список пунктов для галочки:

- Каталог товаров наполняется во вкладке «Каталог» (см. выше).
- Каждый месяц вводится посчитанное количество по каждому товару; рядом
  показывается количество за предыдущий месяц и разница (+/-).
- Есть чек-бокс «Переучёт сверен с Küchenleiterin».
- Два варианта печати: пустой бланк для обхода кухни с ручкой, и версия
  с уже введёнными в приложении цифрами.
- Поле «Дата фактического подсчёта» — конкретный день, когда считали (не весь
  месяц целиком). Именно от этой даты отталкивается расчёт остатков во вкладке
  «Остатки» (см. ниже), поэтому её стоит проставлять честно.

## Расчёт остатков (Склад & FIFO → Остатки)

Автоматический расчёт текущего количества по складу: сколько было на момент
последнего переучёта конкретного товара, плюс что докупили после этой даты,
минус что ушло в готовку по рецептам. Пример из жизни: переучёт 10-го числа
показал 6 кур → 12-го закупили ещё 3 → 14-го приготовили бульон по рецепту,
куда уходит 2 курицы на порцию → остаток на сегодня посчитается как 6 + 3 − 2 = 7.

- **Рецепты** — блюдо и список ингредиентов (товар из каталога + расход за
  одно приготовление). Например, «Бульон»: Курица × 2. Поле продукта —
  текстовое с подсказками (`datalist`, `id="product-nomenclature"`), а не
  `<select>`: с каталогом в ~70 позиций обычный выпадающий список на телефоне
  неудобно листать и он не открывает клавиатуру для поиска. Название нужно
  выбрать из подсказки (или ввести точно как в каталоге) — иначе при
  сохранении покажется явная ошибка «продукт не найден». Рецепты можно
  редактировать (иконка карандаша на карточке — открывает его в форму ниже,
  «Сохранить изменения» вместо создания нового) и импортировать из Google
  Таблиц (кнопка «Импорт из таблиц» в заголовке секции): столбцы
  **Блюдо, Ингредиент, Кол-во**, по одной строке на ингредиент — несколько
  строк с одним названием блюда объединяются в один рецепт.
- **Приход** — лог закупок: товар (тоже текстовое поле с подсказками), количество, дата.
- **Расход** — лог того, что реально готовили: рецепт, сколько раз, дата.
  Расход по ингредиентам считается автоматически из рецепта.
- **Текущие остатки** — для каждого товара из каталога показывает расчётное
  количество на сейчас и дату, от которой считает (последний переучёт с
  заполненным количеством по этому товару). Если переучёта по товару ещё не
  было — показывает «—», расчёт невозможен без стартовой точки.

Вся логика расчёта — в `src/utils/stockBalance.js`, это чистая функция без
побочных эффектов, если понадобится изменить формулу.

## Печать

Кнопки «Печать» есть в трёх местах:
- **Дашборд** → «Задачи для Küchenhilfe» — печатает список задач на сегодня
  по категориям с пустыми чекбоксами (для передачи бумажной копии помощнику).
- **Меню** → «Печать меню на месяц» — таблица на весь месяц с пометкой
  кошерных блюд.
- **Склад & FIFO → Переучёт** — пустой бланк или с текущими данными.

Технически каждая кнопка открывает **новую вкладку** с отдельным, самодостаточным
HTML-документом (`src/utils/printReport.js`) и сразу вызывает на ней `window.print()`.
Первый вариант — скрывать всё, кроме одного блока, через `@media print` в самой
странице — оказался ненадёжным на мобильных браузерах (пустые листы при печати),
поэтому печать полностью вынесена в отдельный документ, не зависящий от разметки
и состояния основного приложения. Если браузер блокирует всплывающие окна,
приложение покажет предупреждение — разрешите всплывающие окна для сайта.

## Резервная копия (Дашборд → «Резервная копия данных»)

Все данные — только в `localStorage` этого браузера. Кнопка «Скачать копию (JSON)»
выгружает всё (`src/utils/backup.js`) в один файл; «Загрузить копию из файла»
читает такой файл, показывает превью (дата экспорта, количество разделов) и
только после явного подтверждения перезаписывает текущие данные и перезагружает
страницу. Экспорт/импорт автоматически подхватывает все ключи `kitchenOS_*`,
включая те, что появятся в будущих версиях — ничего не нужно перечислять вручную.

## История (архив по дням/неделям/месяцам)

- **Дашборд** → «История смен»: список прошлых дней с отметками об открытии/закрытии
  смены и количеством выполненных задач.
- **Уборка**: стрелки листают дни (ежедневный чек-лист) и недели (углублённая уборка)
  независимо друг от друга; будущие периоды заблокированы, «Вернуться к сегодня/неделе»
  возвращает на текущий период одним нажатием.
- **Склад & FIFO → Проверка / Переучёт**: общая стрелка месяцев над обеими вкладками —
  можно посмотреть или доисправить данные за прошлый месяц.

## Библиотека блюд (Меню)

Каждое введённое название блюда (вручную или через импорт) запоминается отдельно
по типу блюда (суп/горячее/гарнир/салат) в `dishLibrary` и подсказывается через
нативный `<datalist>` при вводе в других днях/месяцах — не нужно каждый раз
печатать одно и то же название заново.

## Подтверждение перед удалением

Все кнопки удаления (задачи, продукты, позиции FIFO, товары переучёта, чеки)
требуют двойного нажатия: первое переводит кнопку в состояние «Точно?» на
~2.5 секунды, повторное подтверждает удаление. Это защищает от случайных
срабатываний мокрыми/в перчатках руками без модальных окон поверх интерфейса
(`ConfirmDeleteButton` в `src/components/UI.jsx`).

## Фото чеков (Финансы)

Фото с камеры телефона (`capture="environment"`) часто весит 10–30 МБ на
современных сенсорах — попытка сохранить такой файл как есть (сначала
напрямую, затем через IndexedDB) на практике приводила к падению браузера
с ошибкой «не хватает памяти» на телефоне и откату приложения на Дашборд.

Поэтому сразу после выбора/съёмки фото пережимается на клиенте
(`src/utils/imageCompress.js`, `createImageBitmap` + canvas, до 1100px по
большей стороне, JPEG качество 0.6) и превращается в компактную base64-строку
(`canvas.toDataURL`). Эта строка хранится прямо в записи чека в `localStorage`
— так же надёжно, как и все остальные данные приложения, без отдельного
хранилища вроде IndexedDB, которое на практике оказалось нестабильным в
некоторых мобильных браузерах/встроенных webview. У чеков с фото есть иконка
изображения — открывает фото в новой вкладке. Если фото не удалось обработать
(редкий, повреждённый или неподдерживаемый формат), чек всё равно сохранится,
просто без фото, с явным предупреждением об этом.

## Особенности по разделам

- **Дашборд** — открытие/закрытие смены, задачи для Küchenhilfe (3 категории), контроль
  стратегических запасов (мясо/вино/напитки/базовые продукты) с индикатором "сколько дней
  не проверялось", учёт текущих закупок овощей/фруктов, обратный отсчёт до дедлайнов
  подачи меню и финансового отчёта.
- **Меню** — помесячное планирование, по умолчанию 5 блюд на день (Суп, Горячее,
  Гарнир, Салат, Напиток), кнопка «Добавить блюдо» на случай, если пяти мало —
  список блюд на день полностью динамический, можно переименовать позицию
  (например, вместо «Блюдо 6» написать «Десерт») или удалить любую. Флаг кашрута
  отдельно для каждого блюда. Кнопка «Отправить меню» собирает текст и открывает
  `mailto:` с адресом Küchenleiterin (указывается в этой же вкладке); «Копировать»
  — то же самое текстом в буфер обмена.
- **Склад & FIFO** — список продуктов с автосортировкой по сроку годности
  (красный — сегодня/завтра, жёлтый — 2-3 дня), отметка действия с остатками
  (хранение / заморозка / утилизация), чек-лист месячной инвентаризации по трём
  зонам, полный переучёт с сохранением количества по товару, и вкладка «Остатки»
  с автоматическим расчётом текущего количества по приходу/расходу (подробнее
  ниже).
- **Уборка** — ежедневный чек-лист после смены + отдельный еженедельный чек-лист
  углублённой уборки (ключ по ISO-неделе, обнуляется каждую новую неделю).
- **Финансы** — бюджет аванса на 2-недельный период, лог чеков с категорией и
  фото (`accept="image/*"`), автоподсчёт остатка («Потрачено» считается
  автоматически по добавленным чекам — вручную это поле не редактируется).
  Сумма чека обязательна: без неё чек не сохранится, приложение подскажет об
  этом явно. Кнопки «Отправить» (email) и «Копировать» (текст отчёта в буфер
  обмена — на случай, если `mailto:` не откроется в мобильном браузере).

Красная точка на нижней навигации появляется, когда во вкладке есть что-то срочное
(товар скоро истекает, дедлайн близко, чек-лист не закрыт).
